מפתח API חשוף באתר שבניתם ב-AI: איך בודקים ומה עושים

כשמחברים אתר לשירות חיצוני, כמו מערכת סליקה, ChatGPT או CRM, מקבלים מפתח. חלק מהמפתחות נועדו להיות גלויים, ואחרים שווים כסף למי שמוצא אותם. הנה איך יודעים מה יש אצלכם, ומה עושים אם מפתח סודי כבר יצא החוצה.

מפתח API חשוף הוא מפתח סודי שנמצא בקוד שהדפדפן של הגולש מקבל. כל מי שיודע לפתוח את כלי המפתחים בדפדפן יכול להעתיק אותו ולהשתמש בו על חשבונכם: לשלוח בקשות ל-ChatGPT, לקרוא את מסד הנתונים או לבצע פעולות במערכת הסליקה. הכלל הפשוט: מפתח סודי צריך לשבת בשרת, אף פעם לא בקוד של העמוד.

יש מפתחות שמותר שיהיו גלויים?

כן, וזה מבלבל הרבה אנשים. חלק מהשירותים מנפיקים שני סוגי מפתחות: אחד לדפדפן ואחד לשרת. Supabase משתמשת בדימוי טוב: המפתח הציבורי הוא כמו מפתח שמודבק על דלת הבניין ופותח רק את הלובי, והמפתח הסודי הוא מפתח מאסטר לכל הדירות.

ויש מקרה ביניים: לפי Lovable, מפתחות שהספק תכנן לשימוש בדפדפן, כמו מפתח דפדפן של Google Maps, שייכים לקוד של העמוד, ומגבילים אותם לדומיינים שלכם.

איך מפתח סודי מגיע לדפדפן בכלל?

בדרך כלל באחת משלוש דרכים:

  1. הכלי כתב את המפתח ישירות בקוד, כי ביקשתם "תחבר את ChatGPT" והוא בחר בדרך הקצרה.
  2. המפתח נשמר במשתנה שמתחיל ב-VITE_. הרבה אתרים שנבנים בכלי AI משתמשים ב-Vite. לפי התיעוד של Vite, משתנה שמתחיל ב-VITE_ נכנס לקוד שנשלח לדפדפן. השם נראה "מוסתר" בקובץ .env, אבל הערך גלוי לכל גולש.
  3. הקוד נשמר ב-GitHub ציבורי עם קובץ .env או עם המפתח בתוך הקוד. גם אם מחקתם אותו אחר כך, הוא נשאר בהיסטוריה.

איך עושים את זה נכון ב-Lovable

לפי התיעוד של Lovable, יש מקום מיוחד למפתחות שנקרא Secrets. הערכים שם מוצפנים, נטענים לפונקציות שרצות בשרת (Edge Functions, או server functions בפרויקטים חדשים) ולא מגיעים לדפדפן. אחרי שנשמרו, אי אפשר לראות אותם שוב, רק להחליף או למחוק. מנהלים אותם תחת More → Settings → Secrets.

בדרך כלל לא צריך להוסיף אותם ידנית: כשפיצ'ר צריך מפתח, Lovable מבקשת אותו דרך שדה מאובטח בצ'אט. ולשירותים נפוצים יש Connectors, שבהם המפתח נשמר מחוץ לקוד של האפליקציה לגמרי.

בכלים אחרים, כמו Bolt, ‏Cursor או v0, העיקרון זהה גם אם השמות שונים: המפתח הסודי נשמר במשתנה סביבה בצד השרת, והקוד שרץ בדפדפן פונה לשרת שלכם ולא ישירות לשירות.

איך בודקים אם יש אצלכם מפתח חשוף

הדרך הכי פשוטה היא לבקש מהכלי לעשות בדיקה, בלי לשנות כלום:

פרומפט להעתקה

בלי לשנות שום קוד: תחפש בכל הפרויקט מפתחות API, טוקנים וסיסמאות. כולל קבצי .env, משתנים שמתחילים ב-VITE_ או NEXT_PUBLIC_, וערכים שכתובים ישירות בקוד.
לכל אחד תכתוב: לאיזה שירות הוא שייך, אם הוא נשלח לדפדפן או נשאר בשרת, ואם לפי התיעוד של השירות מותר שהוא יהיה גלוי.
תסמן באדום כל מפתח סודי שמגיע לדפדפן.

ב-Lovable, הסריקה העמוקה (Deep scan) בודקת בין היתר סודות שנמצאים בקוד או במאגר. ומי שרוצה לבדוק לבד: פותחים את האתר החי, לוחצים F12, נכנסים ללשונית Sources ומחפשים (Ctrl+Shift+F) מילים כמו sk_, secret או api_key.

מצאתם מפתח סודי חשוף? ככה מתקנים

  1. לא ממהרים למחוק מהקוד. קודם מבינים איך הוא הגיע לשם, כדי שהמפתח החדש לא יגיע לאותו מקום. גם Supabase ממליצה לתקן קודם את שורש הבעיה.
  2. מעבירים את הקריאה לשרת. בעזרת הפרומפט למטה.
  3. מחליפים את המפתח. נכנסים ללוח הבקרה של השירות, יוצרים מפתח חדש, שומרים אותו ב-Secrets, ורק אז מבטלים את הישן. ב-Supabase התהליך הזה מתואר במסמך על מפתחות API.
  4. בודקים שימוש חריג. חיובים לא מוכרים אצל ספק ה-AI, פעולות לא מוכרות במערכת הסליקה, או שינויים במסד הנתונים.

פרומפט להעתקה

המפתח של [שם השירות] נמצא כרגע בקוד שנשלח לדפדפן. תעביר את כל הקריאות לשירות הזה לפונקציה בצד השרת, שתקרא את המפתח מ-Secrets בשם [SERVICE_API_KEY]. הקוד בדפדפן יפנה רק לפונקציה שלנו.
תוודא שהמפתח לא מופיע יותר באף קובץ שנשלח לדפדפן ולא בשום משתנה שמתחיל ב-VITE_.
אחרי זה תבקש ממני להזין מפתח חדש בטופס המאובטח. את הישן אני אבטל בעצמי.

למה לבטל ולא רק להסתיר? מפתח שהיה גלוי באתר חי, אפילו לכמה שעות, יכול היה להיאסף. אחרי שמחליפים אותו, המפתח הישן כבר לא שווה כלום, גם אם מישהו שמר אותו.

מתי כדאי לקרוא למישהו?

אם מצאתם מפתח סודי חשוף של מערכת סליקה, של מסד נתונים עם מידע על לקוחות, או של שירות שגובה כסף לפי שימוש, ואתם לא בטוחים שהתיקון מלא, כדאי שמישהו יעבור על זה. אני בודק אתרים שנבנו בכלי AI, מעביר את מה שצריך לשרת ומוודא ששום דבר סודי לא נשאר בדפדפן. המחיר נקבע אחרי שיחה קצרה. ואם אתם עוד בשלב התכנון, מדריך האפיון יעזור לחשוב מראש לאילו שירותים האתר יתחבר.

שאלות נפוצות על מפתחות API חשופים

איך אדע אם מפתח מסוים מותר שיהיה גלוי?

בודקים בתיעוד של השירות שהנפיק אותו. שירותים כמו Supabase ו-Stripe מסמנים במפורש מפתחות שמותר לחשוף, ומכנים אותם publishable. כל מפתח שנקרא secret, private, service_role או token אישי צריך להישאר בצד השרת.

מחקתי את המפתח מהקוד. זה מספיק?

לא. אם המפתח היה בקוד שפורסם, או נשמר בהיסטוריה של GitHub, צריך להניח שמישהו כבר ראה אותו. הדרך הבטוחה היא לבטל אותו אצל השירות שהנפיק אותו וליצור מפתח חדש.

מה ההבדל בין Secret ב-Lovable למשתנה שמתחיל ב-VITE_?

Secret נשאר בשרת, VITE_ מגיע לדפדפן. לפי Lovable, ‏Secrets מוצפנים, נטענים לפונקציות בשרת ולא מגיעים לדפדפן. לפי התיעוד של Vite, משתנה שמתחיל ב-VITE_ נכנס לקוד שנשלח לגולש, ולכן מתאים רק לערכים ציבוריים.

האם מותר להדביק מפתח בצ'אט של כלי ה-AI?

עדיף להשתמש בטופס המאובטח. Lovable בדרך כלל מבקשת מפתחות דרך שדה מאובטח בצ'אט, ושומרת אותם כ-Secret. בכלים אחרים, כדאי לשאול איפה המפתח נשמר לפני שמדביקים אותו, ולא להכניס מפתח סודי לקובץ שנשלח לדפדפן.
